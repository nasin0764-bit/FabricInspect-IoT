\subsection{System Performance and Scalability}\label{sec:res-live}

\emph{Methodology.} An hour-long sweep with up to 32 station processes, a broker, and an edge server on one laptop proved unsuitable for timing: under sustained load the host repeatedly entered power-limited states in which both station and edge code ran 4--8$\times$ slower, and the stations competed for cores that real stations would not share. We therefore measure the service-time distributions of every component in short, speed-checked runs (station model: 300 frames on one core; edge: 60 batches for each $b=1\ldots8$; JPEG payloads of all test frames) and feed them into a trace-driven discrete-event simulator of the system in Fig.~\ref{fig:arch}: periodic capture, a single-core station, a FIFO uplink per station with the emulated rate and delay, a single batching edge server ($b_{\max}=8$), and the downlink delay. About 15\,\% of the edge samples were 5--10$\times$ slower than the median because of the same host throttling; samples above twice the median are excluded, and the effect of a slower edge is studied explicitly below. The only free parameter, a constant messaging and serialisation overhead per offloaded frame, is calibrated on a single live configuration (Wi-Fi, edge-only, $N=1$), giving 38.7\,ms.

\emph{Validation.} Table~\ref{tab:validation} compares the simulator with short live runs of the complete system (Mosquitto broker, edge server, station processes, emulated links; 12\,s per configuration with speed checks before and after). On Wi-Fi the simulated median latency of the offloading policies is within 7\,ms of the live value for the cascade (115 vs.\ 108\,ms, 94 vs.\ 99\,ms) and the p95 within 28\,ms; for edge-only with $N=4$ the live p95 is 60\,ms higher. Deadline-miss rates agree in every Wi-Fi configuration, and on the constrained link within 15 percentage points. The live edge server was 1.4--2.6$\times$ busier than simulated in the unflagged configurations, because on the testbed it shares the CPU with the station processes and the broker; the ``edge 2$\times$ slower'' scenario below brackets this case. Four live configurations show clear signs of transient host throttling (marked $\dagger$) and are reported for completeness.

\emph{Scaling on Wi-Fi.} Fig.~\ref{fig:sim} and Table~\ref{tab:sim} report 10 simulated minutes per configuration. Station-only inspection is trivially scalable---each decision takes 40\,ms (p95) on the station's own core and no uplink is used---but inherits the station model's accuracy (F1 0.659, Section~\ref{sec:res-gate}). Edge-only inspection meets the 200-ms deadline for up to $N=16$ stations (p95 154\,ms, 0.3\,\% misses) at which point the edge server is saturated ($\rho=0.99$); at $N=24$ virtually every decision is late. The gated cascade supports $N=24$ stations (p95 155\,ms, 0.2\,\% misses, $\rho=0.87$) and degrades gracefully beyond: at $N=32$ only 13.6\,\% of decisions miss the deadline, and even in overload at most the offloaded half of the frames is late, because clear cases are still decided locally. With an edge server that is twice as slow, the cascade supports 8 stations and edge-only 4. The cascade thus raises the number of stations per edge server by 1.5--2$\times$ while delivering 99\,\% of the edge-only F1, and it reduces the mean uplink per station from 821 to 504\,kbit/s.

The load model (\ref{eq:load}) with the measured $\mu(8)=96$ frames/s and the measured offload fractions (dashed lines in Fig.~\ref{fig:sim}) predicts saturation at $N_{\max}=\mu/(fo)\approx19$ stations for edge-only and $\approx37$ for the cascade ($o=0.52$), consistent with the simulated knees between 16--24 and 24--32 stations; at light load it underestimates utilisation because batches are small and $\mu(1)=64$ frames/s. It is therefore a useful first-order sizing rule for an operator: one CPU edge server per $\approx\!\mu/(fo)$ stations.

\emph{Constrained uplinks.} At 1\,Mbit/s the transmission of a single 14--26\,kB offload takes 110--210\,ms, which alone exhausts the 200-ms budget. Edge-only decisions are therefore always late (100\,\% misses for every $N$), the cascade misses essentially its offloaded fraction (51--53\,\% for $N\ge8$), and only station-only inspection meets the deadline. On such links the station model must take all time-critical decisions; offloaded verdicts remain useful as delayed quality records, or the payload must shrink (smaller crop or stronger JPEG compression), which the gate makes cheap because only uncertain frames are sent.
