\subsection{Tiers}
Fig.~\ref{fig:arch} shows the three tiers.

\emph{Station node.} Each seaming machine carries a USB (UVC) camera looking at the fabric immediately in front of the seam line and a small computer (in our installation the machine's Android controller; in the experiments a single CPU core). The station holds only the station profile of the current fabric, scores each frame with the Gabor--Gaussian detector (Section~\ref{sec:gg}), and applies the confidence gate (Section~\ref{sec:gate}). Clear cases are decided locally; uncertain frames are JPEG-encoded and published to the edge.

\emph{Edge server.} A single plant-level server (any x86 machine; no GPU) subscribes to offloaded frames of all stations, groups pending requests into micro-batches of up to $b_{\max}=8$, scores them with the PatchCore-lite model of the corresponding fabric (Section~\ref{sec:pc}), and publishes the result to the requesting station.

\emph{Profile registry.} When an operator learns a new fabric, the registry fits both models from the same $k$ frames, computes both LOO thresholds, publishes the station profile as a \emph{retained} MQTT message, and stores the edge profile on the server. Because the broker keeps the last retained message per topic, a station that starts, reboots, or switches to that fabric receives the model immediately on subscription, without any polling or file transfer service.

\subsection{Protocol}
All communication uses MQTT~3.1.1~\cite{mqtt311} through a standard broker (Mosquitto~\cite{light2017mosquitto} in our experiments). Table~\ref{tab:topics} lists the topics. Offload payloads carry a 4-byte header length, a JSON header (sequence number, fabric, timestamp), and a $256\times256$ JPEG crop (quality 85); results and verdicts are small JSON objects. QoS~1 is used for profiles, offloads and results, QoS~0 for verdicts, which are informational.

\subsection{Operator Workflow and Implementation}
In \emph{learn} mode the operator types the fabric name and slowly moves defect-free material under the camera; a frame is grabbed every 0.4\,s until $k$ frames (default 10) are collected. In \emph{inspect} mode each frame is centre-cropped to a square region of interest, scored, and shown with a heat-map; regions above threshold are outlined, and every decision is appended to a CSV log while defective frames are saved for review. A desktop GUI, a command-line interface, and the three IoT roles (\texttt{station}, \texttt{edge}, \texttt{publish}) share one detector module, so the numbers reported in this paper are produced by the code an operator runs. The implementation uses Python~3.9, OpenCV, SciPy, Eclipse Paho, and PyTorch/torchvision (CPU build) with public ImageNet ResNet-18 weights~\cite{he2016resnet}.
